# 输出与交互格式

## 列表回答

第一行直接给数量：

> 严格符合 **N 件**；相关藏品 **M 件**。

随后用一行说明检索口径：

> 严格口径：南宋 + 官窑；相关口径：宋、宋至元、宋元、宋金等编目中的官窑记录。

先列严格结果，再列相关结果。每条采用：

```markdown
1. 《藏品名称》
   朝代：……｜窑口/作者：……｜工艺/釉色：……
   馆藏：……｜馆藏号：……｜数据编码：……
   命中：……
   操作：回复“查看 1”或“查相似 1”
```

字段为空时省略；关键字段应有但数据库未提供时明确写“数据库未提供”。默认每组最多展示 10 件，并说明是否还有更多。

如果严格结果为 0，仍需先写“严格符合 0 件”，再解释最接近的相关口径。不要把相关结果挪成严格结果。

## 图片回答

在数量后增加简短观察：

```markdown
图片线索：
- 直接可见：……
- 推测（中等置信）：……
- 尚不能判断：……
```

再列馆藏相似记录。结尾注明：

> 以上是馆藏资料相似性检索，不构成实物真伪、年代或市场价值鉴定。

## 详情回答

标题使用藏品名称，并按数据可用性依次展示：

1. 身份：名称、分类、作者、时代、年代、地域、窑口、流派。
2. 制作：材质、工艺、釉色、纹饰、器型、装裱。
3. 文字：款识、释文、书体。
4. 尺度：尺寸、重量。
5. 馆藏：机构、馆藏编号、文物级别。
6. 记录：说明、来源递藏、展览、参考文献。
7. 图片：按顺序提供缩略图或原图链接；说明图片数量。

结尾提供：

- “回复‘返回列表’查看原结果”
- “回复‘查相似’按本件的时代、窑口、工艺、釉色、纹饰和器型继续检索”
- “回复‘比较 1 和 3’生成字段对照”

## 比较回答

两件及以上藏品比较时，用紧凑表格展示共同字段：时代、作者/窑口、材质、工艺、釉色、纹饰、款识、器型、尺寸、馆藏。表格后分开写：

- 共同点
- 关键差异
- 哪些差异来自数据库缺失，哪些来自明确记录
- 可继续检索的专业词

## 链接与操作

- 有真实图片 URL、来源 URL 或馆方详情 URL时才创建 Markdown 链接。
- 没有真实详情 URL 时，不为名称编造链接。
- 客户端支持 MCP Apps UI 时，把名称、查看详情、相关藏品绑定到真实工具调用。
- 纯文本客户端统一使用稳定序号和 `coll_code`，确保后续指令可恢复。
